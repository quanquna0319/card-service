# 08 · 魔盒授权协议桥接

把本项目的卡密体系接到 **魔盒 3.1.0** 的私有协议上。

一个进程、一个端口，同时提供两套接口：魔盒的 `card/sign`·`card/active`·`card/info`·`feature/list`·`launch/sign`·`launch/check`·`map/key`，以及本项目原有的管理后台与 `/api/*`。

卡密不再"一律放行"，而是**直接查本项目的 SQLite 库**：只有后台签发、未过期、未禁用、设备匹配的卡密，才能激活魔盒。

```
┌────────────┐  /card/sign /card/active   ┌────────────────────┐
│ 魔盒 APK   │ ─────────────────────────▶│ bridge :8080        │
└────────────┘   account = 卡密            │  ├ 魔盒协议适配层    │
                                          │  └ 复用本项目的       │
┌────────────┐  /api/login /api/cards/...  │     Handler        │
│ 浏览器后台 │ ─────────────────────────▶│        │            │
└────────────┘                            └────────┼────────────┘
                                                  ▼
                                            cards.sqlite3
```

## 快速开始

```bash
# 1) 起服务（在仓库根目录）
CARD_SECRET=你的密钥 python mitm_server.py \
  --port 8080 --host 0.0.0.0 \
  --card-service . \
  --card-db ./cards.sqlite3 \
  --state ./mitm_state.json

# 2) 浏览器打开 http://<本机IP>:8080/ 登录后台，生成卡密
# 3) 魔盒里输入卡密激活
```

`--card-service` 指向本项目根目录（含 `server.py`）。找不到时会退化为"一律放行"的 Mock 模式，并打印警告。

## 卡密格式

生成的就是本项目原生的 5 段式：

```
2AC6-QWGJ-HANJ-7UNO-6EP2
└──── 16 位载荷 ────┘ └校验┘
```

魔盒输入框能完整接收 24 位（实测未截断），直接填即可。

**唯一的转换点在 `account` 字段**：魔盒把它当 AES-128 密钥（`aa.ah.av(str, key)`），必须 16 字节，否则客户端协程会抛异常并静默中断（表现为点分身毫无反应）。而 `account` 由服务端在 `card/info` 里下发，所以桥接层这样处理：

| 环节 | 做法 |
|---|---|
| 生成 | 原生 24 位 5 段（`--card-format dash`，默认） |
| 校验 | 依次尝试：原样 → 大写 → 去横杠 20 位 → 补全校验码 |
| 回显 account | 取前 16 位载荷，满足 AES 长度 |

### 校验码可反推

本项目的校验码是确定性派生：

```
check = base32( hmac_sha256(CARD_SECRET, 前16位载荷)[:3] )[:4]
```

拿到前 16 位就能算出完整 24 位卡号。因此：

- 输入被截断成 16 位 → 自动补全，照样能查库
- 最后一段打错 → 按载荷重算正确校验码，仍能识别
- 漏写 / 多加横杠 → 归一化后匹配

> 副作用：魔盒「我的」页面显示的是 16 位载荷（`2AC6QWGJHANJ7UNO`），不是带横杠的原文 ——
> `account` 既是显示值又是 AES 密钥，无法两者兼得。后台列表里仍是完整卡号。
> 若不想要这个差异，用 `--card-format 16` 直接生成 16 位卡密。

## 参数

| 参数 | 默认 | 说明 |
|---|---|---|
| `--port` | 8080 | 监听端口 |
| `--host` | 0.0.0.0 | 监听地址 |
| `--card-service` | `card-service` | 本项目目录（含 `server.py`） |
| `--card-db` | `cards.sqlite3` | 卡密库路径 |
| `--card-secret` | `LICENSE_BLOB` | **必须与建库时一致**，否则所有卡密都"不存在" |
| `--app-id` | `com.sandbox.dsim` | 与卡密绑定的应用标识 |
| `--card-format` | `dash` | `dash`=原生 24 位 / `16`=纯载荷 |
| `--allow-any` | 关 | 调试：跳过校验一律放行 |
| `--state` | `mitm_state.json` | 会话持久化（重启免重新激活） |

环境变量 `CARD_SECRET` / `CARD_DB` / `CARD_APP_ID` 同样生效。

## 接口映射

| 魔盒端点 | 行为 |
|---|---|
| `POST /card/sign` | 回挑战串（与真服务端一致，此步不查库） |
| `POST /card/active` | **查库校验**，通过则签发会话 token |
| `POST /card/info` | 凭 `m-token` 返回 account / 到期时间 / 套餐名 |
| `POST /feature/list` | 返回 4 项功能（位置/相机/WIFI/品牌保护） |
| `POST /launch/sign`·`/launch/check` | 返回启动令牌（分身启动必需） |
| `POST /map/key` | 百度地图 AK（虚拟定位用） |
| 其他 | 交给本项目的 Handler（后台、`/api/*`、静态页） |

校验失败时把服务端原话回给客户端，App 会原样弹出来：

```
{"ret":1,"result":null,"msg":"卡密不存在"}
{"ret":1,"result":null,"msg":"卡密已过期"}
{"ret":1,"result":null,"msg":"卡密已绑定其他设备"}
```

## 注意

1. **`CARD_SECRET` 不能丢、不能改**。换掉后库里所有卡密立刻失效且不可恢复。
2. **一卡一机**。首次激活绑定 `app_id + imei`；换设备会被拒。同一设备重激活需先清 App 数据。
3. **服务端要常开**。关闭后激活状态仍在，但启动分身会因拿不到 `launch/check` 令牌而报"网络连接错误"。
4. **仅适配魔盒 3.1.0**。接口路径与字段名是这一版逆向出来的，换版本需重新对齐。

## 已验证

- 完整 24 位 / 截断 16 位 / 去横杠 20 位，三种写法同一设备全部通过
- 旧 16 位卡向后兼容
- 真机（Android 15）激活成功：`2AC6-QWGJ-HANJ-7UNO-6EP2` → 月卡，到期 2026-11-24
